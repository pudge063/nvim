## Файлы и поиск (Telescope)

Короткая таблица ниже — самое частое. Полный разбор (мультивыбор,
синтаксис нечёткого поиска, чем `live_grep` принципиально отличается
от `find_files`, что уже включено по умолчанию) — в отдельном файле
**[SEARCH.md](SEARCH.md)**.

| Клавиши | Действие | Когда использовать |
|---|---|---|
| `<leader>ff` | Найти файл по имени (скрытые файлы уже видны по умолчанию) | Открыть файл, зная (примерно) его название |
| `<leader>fF` | То же, плюс файлы из `.gitignore` (venv, node_modules...) | Файл лежит внутри `.venv`/`node_modules` |
| `<leader>fg` | Найти текст по содержимому файлов (grep, скрытые файлы уже включены) | Ищете, где используется переменная/строка |
| `<leader>fG` | То же, плюс содержимое из `.gitignore` | Текст может быть внутри venv/сборки |
| `<leader>fb` | Список открытых буферов | Быстро прыгнуть между уже открытыми файлами |
| `<leader>fr` | Недавно открытые файлы | «Я это недавно открывал, но закрыл» |
| `<leader>fh` | Поиск по `:help` | Как что-то работает в самом nvim |
| `<leader>fd` | Список диагностик (ошибки/warning) | Обзор всех проблем в проекте/файле |
| `<leader>fs` | Символы (классы/методы) **текущего файла** | Оглавление файла — быстро прыгнуть к нужному методу |
| `<leader>fS` | Символы (классы/методы) **всего проекта** | Найти класс/метод по имени, не помня файл |

Внутри Telescope (когда открыто окно поиска):
| Клавиши | Действие |
|---|---|
| `<C-n>` / `<C-p>` или `↓`/`↑` | Следующий / предыдущий результат |
| `<CR>` | Открыть выбранное (или все выделенные, см. `<Tab>`) |
| `<C-x>` / `<C-v>` / `<C-t>` | Открыть в горизонтальном / вертикальном сплите / новом табе |
| `<Tab>` | Отметить элемент для мультивыбора |
| `<Esc>` (дважды, если в insert) | Закрыть Telescope |
| `<C-q>` | Отправить все (или отмеченные) результаты в quickfix-список |

Подробности каждого пункта, включая примеры синтаксиса нечёткого
поиска (`'exact`, `^prefix`, `suffix$`, `!exclude`) и то, почему
`live_grep` — это regex ripgrep, а не нечёткий поиск — в
[SEARCH.md](SEARCH.md).

## Дерево файлов

| Клавиши | Действие |
|---|---|
| `<leader>e` | **Умный тоггл**: дерево закрыто → открыть и сфокусировать; открыто, но фокус не там → переключить фокус на дерево; фокус уже там → закрыть |

Внутри дерева (neo-tree), когда оно в фокусе:
| Клавиши | Действие |
|---|---|
| `<CR>` / `o` | Открыть файл / развернуть папку |
| `s` | Открыть файл в **vertical split** |
| `S` | Открыть файл в horizontal split |
| `t` | Открыть файл в новой вкладке |
| `w` | Открыть с выбором окна (window-picker), если сплитов несколько |
| `a` | Создать файл (папку — если ввести имя со `/` на конце) |
| `d` | Удалить |
| `r` | Переименовать |
| `y` / `x` / `p` | Скопировать / вырезать / вставить (файл) |
| `H` | Показать/скрыть скрытые файлы |
| `R` | Обновить дерево |
| `<C-l>` (или просто ваш обычный window-nav, см. [Окна](#окна)) | Вернуться в редактор |

## Навигация по коду / LSP / ООП

Работает в любом файле, где подключён LSP (Python — везде, где есть `.venv`/pyright).

| Клавиши | Действие | Зачем / когда |
|---|---|---|
| `gd` | Go to definition | Перейти к определению класса/функции/переменной |
| `<leader>gd` | Go to definition (**vertical split**) | То же самое, но открывает определение рядом, не заменяя текущий файл в окне |
| `gD` | Go to declaration | К объявлению (реже нужно, полезно для стабов `.pyi`) |
| `gr` | Go to references | Все места, где используется символ под курсором |
| `gI` | Go to **implementations** | Работает не для всех LSP — **pyright не поддерживает** (`implementationProvider` у него не заявлен вовсе, проверено тестом `lsp_spec.lua`). Для Python вместо этого используйте `gr` на базовом классе — см. сценарий ниже |
| `gy` | Go to type definition | От переменной — к определению её типа/класса |
| `K` | Hover | Показать тип/сигнатуру/docstring под курсором |
| `<leader>rn` | Rename | Переименовать символ **сразу везде** в проекте — безопасный рефакторинг |
| `<leader>ca` | Code action | Быстрые фиксы: авто-импорт, «реализовать абстрактные методы» и т.п. Работает и в visual mode на выделении |
| `<leader>ci` | Incoming calls | Кто вызывает этот метод (call hierarchy внутрь) |
| `<leader>co` | Outgoing calls | Что вызывает этот метод (call hierarchy наружу) |
| `<leader>d` | Диагностика строки целиком | Полный текст ошибки/warning под курсором (если не влезает в одну строку справа) |
| `<C-h>` (**в insert mode**) | Signature help | Подсказка параметров функции прямо во время набора аргументов |

> `<C-h>` встречается дважды в этом конфиге: в normal mode это переход в
> левое окно (см. [Окна](#окна)), в insert mode — signature help. Конфликта
> нет, это разные режимы.

Типичный сценарий работы с ООП-кодом (Python, pyright):
1. `class Foo(Base):` → курсор на `Base`, `gd` — переходим к базовому классу.
2. Курсор на **имени базового класса** (не метода — см. оговорку про `gI` выше), `gr` — находим все места, где на него ссылаются, включая объявления подклассов (`class Foo(Base):`).
3. `<leader>fs` — быстро пролистываем все методы текущего класса.
4. `<leader>rn` на имени метода — переименовываем везде, включая наследников и вызовы.

`gI` при этом никуда не делся — просто держите в уме, что для Python он
не сработает (LSP ответит "method not supported"); для языков, чей
LSP-сервер implementation умеет (например, `gopls` для Go), это по-прежнему
рабочий и полезный хоткей.

## Автодополнение (blink.cmp)

Работает автоматически в insert mode при вводе.

| Клавиши | Действие |
|---|---|
| `<C-space>` | Открыть меню вручную / показать документацию к выбранному пункту |
| `<Up>` / `<Down>` или `<C-p>` / `<C-n>` | Следующий / предыдущий вариант |
| `<CR>` | Принять выбранный вариант |
| `<C-e>` | Закрыть меню, ничего не принимая |
| `<Tab>` / `<S-Tab>` | Прыжок по плейсхолдерам сниппета (**не** листание меню!) |
| `<C-k>` | Показать/скрыть подсказку сигнатуры |
| `<C-b>` / `<C-f>` | Прокрутить документацию вверх/вниз |

## Форматирование

Форматирует ruff (Python), stylua (Lua), prettier (YAML, Markdown) и taplo
(TOML) — см. также
[раздел про ruff в README](README.md#python-lsp-venv-ооп-навигация).

| Клавиши | Действие |
|---|---|
| `<leader>mp` / `\\` (два раза) | Отформатировать буфer **прямо сейчас** — не зависит от сохранения, работает и в visual mode на выделении |
| `<leader>uf` | Вкл/выкл автоформат при `:w` — только для текущего буфера |
| `<leader>uF` | То же самое, но глобально, для всех буферов |

Автоформат на сохранение включён по умолчанию — `<leader>uf` полезен,
когда правите чужой код в другом стиле и не хотите его переформатировать
целиком одним сохранением.

## Выравнивание

Плагин `mini.align` — для ручного выравнивания по столбцам (то, что ruff
сознательно не делает, поскольку это не часть PEP8).

| Клавиши | Действие |
|---|---|
| `ga` + движение/выделение, затем символ | Выровнять по символу. Например: выделите строки в visual mode, `ga=` — все `=` встанут в один столбец |
| `gA` + то же | То же самое, но с живым превью перед применением |

Пример: есть
```python
x = 1
foo = 2
qux = 3
```
Выделяете все три строки (`Vjj`), жмёте `ga=` — получаете:
```python
x   = 1
foo = 2
qux = 3
```

## Скобки и кавычки (автопары)

Работает сама по себе, без хоткеев — плагин `nvim-autopairs`:
- набрали `(` → появилось `()`, курсор между ними;
- то же для `[`, `{`, `"`, `'`;
- вложенность работает как в IDE: `(["{` → `(["{}"])`.
- Внутри строк/комментариев (treesitter-aware) пары не навязываются там,
  где это обычно мешает.

## Git (gitsigns)

Знаки изменений на левом поле (добавлено/изменено/удалено) появляются
сами для любого файла внутри git-репозитория, хоткеи ниже — для
навигации и работы с ними.

| Клавиши | Действие |
|---|---|
| `]h` | Следующий изменённый хунк |
| `[h` | Предыдущий изменённый хунк |
| `<leader>hs` | Застейджить хунк (работает и в visual mode на части хунка) |
| `<leader>hr` | Откатить хунк (reset) к состоянию из git |
| `<leader>hp` | Превью хунка (diff) во всплывающем окне |
| `<leader>hb` | Blame текущей строки (кто и когда её менял) |
| `<leader>tb` | Вкл/выкл постоянный inline blame (справа от строки) |

## Python venv

| Клавиши | Действие |
|---|---|
| `<leader>cv` | Выбрать виртуальное окружение (Telescope-пикер: находит `.venv`, poetry, conda, pyenv и т.п.) |

Если venv называется `.venv` и лежит в корне проекта — подхватывается
автоматически, `<leader>cv` не нужен (см. README).

## Отладка (DAP)

Точечная отладка с брейкпоинтами — nvim-dap. Для Python работает из коробки
(debugpy ставится через mason). Для C/C++ — через нативный DAP-режим gdb
(`gdb -i=dap`, нужен gdb ≥ 12 в `$PATH`), включая attach к удалённому
gdbserver (OpenOCD/J-Link) для embedded — с полной прошивкой это не
работает, только для подключения к уже запущенному gdbserver-стабу.

| Клавиши | Действие | Зачем / когда |
|---|---|---|
| `<leader>db` | Toggle breakpoint | Поставить/снять брейкпоинт на текущей строке |
| `<leader>dB` | Conditional breakpoint | Брейкпоинт с условием (спросит выражение) |
| `<leader>dc` | Continue / Start | Начать отладку (выберет конфигурацию, если их несколько) или продолжить после останова |
| `<leader>di` | Step into | Зайти внутрь вызываемой функции |
| `<leader>do` | Step over | Выполнить строку, не заходя внутрь вызовов |
| `<leader>dO` | Step out | Выйти из текущей функции наружу |
| `<leader>dt` | Terminate | Завершить сессию отладки |
| `<leader>dr` | Toggle REPL | Консоль отладчика — можно вычислять выражения в текущем контексте |
| `<leader>du` | Toggle UI | Панели со стеком вызовов, переменными и брейкпоинтами (nvim-dap-ui) |

## Терминал

| Клавиши | Действие |
|---|---|
| `<C-\>` | Открыть/свернуть плавающий терминал |
| `<leader>tt` | То же самое — запасной вариант для macOS, где `Ctrl+\` иногда перехватывается раньше nvim (подробности в README) |
| `<Esc>` (когда курсор в терминале) | Выйти из terminal-mode в normal mode, не завершая процесс в терминале |

## Undo / история изменений

| Клавиши | Действие |
|---|---|
| `<leader>u` | Открыть/закрыть визуальное дерево истории (undotree) |

Обычные `u` / `Ctrl-r` / `g-` / `g+` — см. [VIM-BASICS.md](VIM-BASICS.md#undo--redo).
История отмены переживает перезапуск nvim (`undofile = true`).

## Общие

| Клавиши | Действие |
|---|---|

| `<leader>w` | Сохранить файл |
| `<leader>q` | Закрыть окно/буфер |
